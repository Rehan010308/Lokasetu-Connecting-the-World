# LokaSetu V2 — architecture, integrations and bug audit

V2 is a rebuild, not a patch. This document covers what changed, why, and what
is real versus simulated.

---

## 1. What was removed, and why

| Removed | Reason |
|---|---|
| Points system | A number you can grind is a number that stops meaning "good at the job". |
| Worker ranking / leaderboards | Ranking neighbours against each other is the wrong social contract for a trade marketplace. |
| Gamified tiers (Bronze→Hero) | Same. A worker is not a video-game rank. |
| Trust score numbers | "4.6 reliability" is false precision derived from three taps. |
| Match percentage rings ("95%") | Ordering is still computed — it is just no longer *displayed* as a fake-precise score. |
| Streaks and endorsement badges | Engagement mechanics, not trust signals. |

A worker is now judged on exactly five things, all of them facts:
**jobs completed · customer reviews · Aadhaar verification · years of
experience · response time.**

`rankWorkers()` in `lib/ai/match.ts` still orders results — a customer needs a
sensible first result — but it returns `rank` for sorting and `reasons` for
display. The number never reaches the screen.

## 3. Database schema

Every interface in `lib/types.ts` becomes one table. Storage today is
localStorage behind `components/store.tsx`; swapping to Postgres means
rewriting that one file.

```
workers      id, name, phone, lang, languages[], category, services[],
             experience_years, raw_speech, bio, geo, radius_km, availability,
             jobs_completed, rating, review_count, response_mins,
             verification{status, id_last4, id_name, method, checked_at},
             emergency_contact, created_at

clients      id, role(customer|society|business), name, phone, lang, geo,
             org_name, org_type, size, emergency_contact, created_at

jobs         id, client_id, client_role, title, raw_request, lang,
             category, service_id, when_text, budget_min, budget_max,
             urgency, estimated_hours, geo{lat,lng,area,address},
             price_min, price_max, price_basis,
             status, assigned_worker_id, agreed_amount,
             payment_method, payment_status, created_at

messages     id, job_id, from_role, from_id, kind(text|voice|quick),
             text, lang, duration_sec, created_at

reviews      id, job_id, worker_id, author_name, stars, text, tags[], created_at

sos          id, job_id, at, by, lat, lng, resolved
```

Two schema decisions worth defending:

- **`jobs.lang` is never overwritten.** The request stays in the language it
  was spoken in. Nothing silently converts a Tamil request to English.
- **`verification` stores `id_last4` only.** There is no column for a full
  Aadhaar number, so one cannot be written by accident.

## 4. The language system

V1 shipped `Partial` dictionaries with an English fallback. That is exactly how
a Hindi screen ends up with English buttons.

V2 removes the fallback:

```ts
export type TKey = keyof typeof en;
export type Dict = Record<TKey, string>;   // COMPLETE — not Partial
export const hi: Dict = { ... }            // miss one key → build fails
```

**A mixed-language screen is now a compile error.**

- **163 UI keys × 10 languages = 1,630 strings**, all present.
- **47 services + 13 categories × 10 languages = 600 names**, all present.
- The self-test additionally proves no language silently equals English.

Languages: English, हिन्दी, தமிழ், తెలుగు, ಕನ್ನಡ, മലയാളം, मराठी, বাংলা,
ગુજરાતી, ਪੰਜਾਬੀ.

**Voice keeps its script.** `rec.lang` is set from the chosen language
(`speechLocale()` in `lib/i18n.ts`), so Hindi speech returns Devanagari and
Tamil returns Tamil. V1's "everything becomes English" bug was a wrong
recogniser locale, and it is fixed in one place: `useSpeech()` in
`components/kit.tsx`.

**Chat translation without a translator.** Quick replies are stored as
translation *keys*, not text. A worker taps "मैं रास्ते में हूँ"; the customer's
phone renders `m.onWay` in their own language. Zero latency, zero cost, always
correct.

## 5. Category system

The V1 bug — workers appearing under the wrong heading — was structural: one
flat list of trades meant "fan repair" and "wiring" were both just
"electrician".

V2 separates two things:

- **Category** — what a customer browses (13 of them)
- **Service** — what a worker actually does (47 of them)

A service belongs to exactly one category. A worker is tagged with *services*.
Search filters on services:

```ts
if (job.serviceId && !w.services.includes(job.serviceId)) continue;  // hard filter
```

A plumber cannot appear under Painting, because the filter is on service id,
not on a keyword in a sentence. Four self-test assertions lock this in.

## 6. Search experience

The generic "workers near you" map is gone. The flow is now search-first:

```
Home → type or speak what you need
     → best-matching service (or all 13 categories)
     → services inside that category
     → only workers who do that exact service
     → filters: nearest · available now · verified only
```

Someone who cannot type never has to: six large "common needs" tiles cover the
most-requested services, and the mic sits inside the search field.

## 7. AI workflow

| Stage | File | Behaviour |
|---|---|---|
| Speech → profile | `ai/profile.ts` | category, services, years, and a bio **written in the worker's language** |
| Request → job | `ai/request.ts` | service, urgency, duration + a `missing[]` list |
| Follow-ups | `app/post` | asks one question at a time, in the user's language |
| Pricing | `ai/pricing.ts` | transparent rate card, blended with local completed jobs |
| Ordering | `ai/match.ts` | service match → verified → distance → availability → volume |

**The AI never assumes.** If timing, budget or address are not in what the user
said, they come back in `missing` and the posting screen asks. Six self-test
assertions prove nothing is invented:

```
✅ missing timing is asked for
✅ no budget invented when unstated
✅ no address invented when unstated
```

**Phase 2 — real Claude.** Each stub is already `async` and returns a typed
object. Replace one function body with `fetch('/api/...')` and nothing upstream
changes. See `DEPLOY.md` for the route code.

## 8. Aadhaar verification

⚠️ **Simulated, and the UI says so.**

Real Aadhaar authentication is licensed: only a UIDAI-registered AUA/KUA may
call the APIs, and the Aadhaar Act places hard obligations on anyone handling
the data. So `lib/verify.ts` simulates the check while keeping two things
production-real:

1. **Verhoeff checksum validation** — the genuine algorithm UIDAI uses. A
   made-up number fails before any network call, so the failure state in the
   demo is real behaviour, not theatre.
2. **Only the last four digits are ever stored.** The full number lives inside
   one function scope and is discarded. A self-test asserts the stored record
   never contains it.

States: `unverified → pending → verified | failed`, each with its own badge.
Seed data includes all four so every state is visible in a demo.

**To go live:** replace the body of `verifyIdentity()` with a call to a KYC
partner (DigiLocker, Signzy, Karza, IDfy, Cashfree). Signature unchanged.

## 9. Integrations

| Feature | Status now | Upgrade path |
|---|---|---|
| **Calling** | `tel:` links — works on any phone today | Masked calling via Exotel/Twilio: buy a virtual number, POST to `/api/call/connect`. Neither side sees the other's number. |
| **WhatsApp** | `wa.me` deep links — share a worker, send a job, contact. No API key. | WhatsApp Business API for outbound job notifications. |
| **Maps** | `maps/dir/?api=1` deep links — turn-by-turn, opens the native app. No key. | Billed Maps JS + Directions API for a live route and in-app ETA. Keep the deep link as fallback. |
| **SOS** | Real: dials 112, reads GPS, shares a location link, logs the event. | Add a support webhook and SMS to the emergency contact. |

All four are exercised by the self-test.

## 10. SOS flow

Visible only while a job is `on_the_way` or `working` — present when it matters,
absent when it would just be alarming.

```
Press and hold 2 seconds   (deliberate — no accidental triggers)
  → GPS read
  → SOS event written against the job
  → Call 112  ·  Send location on WhatsApp
```

The emergency contact is set in `/me` and stored per person.

## 11. Society and business hiring

`/hire` is a separate flow because bulk hiring differs in three ways: it is
recurring, it is for more than one person, and the buyer is spending someone
else's money.

- Only the categories that org type actually hires (societies see maintenance,
  security, cleaning, gardening, plumbing, electrical; businesses see shop help,
  driving, cleaning, security, electrical)
- Headcount and duration (one time · daily · monthly)
- Estimate scales with headcount, not a single flat figure
- Shows how many workers are actually available before posting

## 12. Bug audit

### Reported in V1 — fixed

| # | Bug | Root cause | Fix | Proof |
|---|---|---|---|---|
| 1 | Language switching leaves English text | `Partial` dictionaries with English fallback | `Dict = Record<TKey,string>` — missing key breaks the build | 1,630 strings asserted |
| 2 | Mixed-language labels | Same | Same | self-test: "no language silently falls back to English" |
| 3 | Voice converts everything to English | `rec.lang` not set from chosen language | `speechLocale(lang)` in one shared hook | — |
| 4 | Workers in wrong categories | Flat trade list, keyword matching | Two-level category→service model, hard filter on service id | 4 assertions |
| 5 | Inconsistent search results | Ranking used soft category scoring | `continue` unless the worker has the exact service | "no painter in a plumbing search" |
| 6 | AI assumes missing info | Defaults for timing/budget/hours | `missing[]` + follow-up questions | 6 assertions |
| 7 | Confusing onboarding | 6-step form wizard | Conversation: AI asks, worker speaks | — |

### Found during the V2 audit — also fixed

| # | Bug | How it surfaced |
|---|---|---|
| 8 | Kannada "ಬಣ್ಣ" (paint) matched no service | self-test — category words existed only on category names, not service keywords |
| 9 | Punjabi "ਕਾਰ" (car) matched no service | self-test — Punjabi/Gujarati/Marathi/Bengali keywords were thin; 74 added |
| 10 | Headings invisible in dark mode | dark-mode render — components relied on inherited colour |
| 11 | Radar rings rendered as ellipses | render — percentage width/height in a non-square box |
| 12 | Activity feed copy read "a electrical job" | self-test regex for broken articles |
| 13 | Missing `toRad` helper in distance maths | typecheck — would have crashed every distance call |

### Known limits (honest list)

- Data is per-browser. Two devices do not see each other yet — Postgres is
  phase 3 in `DEPLOY.md`.
- Aadhaar verification is simulated (section 8).
- Masked calling and live map tracking need paid accounts (section 9).
- The scrap/raddiwala flow and the community insights page from V1 are not yet
  ported to the V2 model. `lib/ai/scrap.ts` is intact and ready.
- Voice needs Chrome, Edge, Android Chrome or iOS Safari 14.5+, and HTTPS.
  Everywhere else it silently falls back to typing.

## 13. Accessibility

Unchanged from Aurora and still enforced: tap targets ≥56px, body text never
below 13px, icon **and** word on every affordance, `prefers-reduced-motion` and
`prefers-contrast` honoured, visible focus rings, `aria-*` on dialogs, the dock
and the mic. See `DESIGN.md` §8.

The V2 additions that matter most for low-literacy users:

- One question per screen during onboarding and posting
- Quick replies mean a worker can hold a full conversation without typing
- Voice notes transcribe, so a customer reads what a worker said
- The SOS button is large, red, and requires a deliberate hold
